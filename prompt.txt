Here is a complete prompt you can give to **OpenCode**:

You are a senior professional full-stack engineer. Design, build, and ship a complete responsive web portal for managing Freshers Expo 2026 / Bazaar stall applications at Mbarara University of Science and Technology.

Build the system using only:

* Core PHP
* MySQL
* JavaScript
* AJAX
* HTML
* CSS

Do not use Laravel, React, Vue, Angular, Bootstrap, Tailwind, or any heavy framework. The system should be lightweight, clean, secure, and easy to deploy on normal shared hosting/cPanel.

Use a professional Mbarara University of Science and Technology inspired color theme. The main theme should feel institutional, official, clean, and modern, using MUST-style colors such as green, yellow/gold, white, and dark accents. Keep the interface youthful and event-friendly but still formal enough for a university-managed activity.

The system must be highly responsive, especially on mobile phones. Many users will access it using smartphones, so mobile usability should be the priority. Menus must not be cluttered. Use a simple collapsible mobile menu, clean cards, clear buttons, readable text, and enough spacing. Avoid overcrowding dashboards with too many items at once.

Project Name:
Freshers Expo Stall Management Portal

Main Purpose:
The portal should help applicants who already filled a Google Form create portal accounts without registering again from scratch. The system should check whether the applicant exists in the Google Form response data using email or phone number. If found, it should allow them to set a password and automatically import their form response details into the portal.

Important User Flow:

1. Applicant first fills the Google Form.
2. Google Form responses are available in a Google Sheet or imported CSV/MySQL table.
3. Applicant opens the portal.
4. Applicant clicks “Create Portal Account.”
5. Applicant enters the same email address or phone number used in the form.
6. Applicant enters preferred password and confirms password.
7. System checks if the email or phone number exists in the imported form responses.
8. Phone numbers should be normalized before matching.
9. If the applicant is found, the system creates their account and imports their details.
10. If the applicant is not found, show a friendly message telling them to first fill in the Google Form or use the same email/phone number used during registration.
11. Applicant logs in and views their application status, payment status, messages, compliance document status, and assigned stall information.
12. Admin logs in and manages applicants, payments, messages, statuses, stall allocations, and reports.

Phone Number Matching Requirement:
The system should treat different Uganda phone number formats as the same number. For example:

0771234567
771234567
+256771234567
256771234567

All should be normalized internally to:

256771234567

Create a reusable PHP function for phone normalization. The system should match applicants using email first and phone number second. Emails should be compared in lowercase and trimmed.

Security Requirements:

1. Use password_hash() and password_verify() for passwords.
2. Use prepared statements with MySQLi or PDO to prevent SQL injection.
3. Validate all form inputs.
4. Escape output properly to prevent XSS.
5. Use secure PHP sessions.
6. Protect admin pages so only admins can access them.
7. Protect user pages so only logged-in users can access them.
8. Add CSRF protection for important forms such as login, account creation, status update, payment verification, messaging, and stall allocation.
9. Do not expose database errors directly to users.
10. Store uploaded files safely.
11. Restrict uploads to PDF, JPG, JPEG, and PNG.
12. Limit upload size.
13. Rename uploaded files securely.
14. Prevent direct execution of uploaded files.

Important Functional Requirements:

1. When an applicant creates an account, automatically create a linked application record.
2. Applicants should not be allowed to create more than one account for the same form response.
3. Admin should be able to manually link or correct applicant records if needed.
4. If an applicant tries to create an account with a phone number that matches multiple records, show a message asking them to contact the organizing committee.
5. If an applicant has already created an account, redirect them to login.
6. Applicant details imported from Google Form should be view-only by default, but admin can correct them.
7. Payment proof uploaded in the portal should be visible to admin immediately.
8. Admin communication should appear in the applicant dashboard.
9. The system should be deployable by uploading files to cPanel and importing the SQL database.
